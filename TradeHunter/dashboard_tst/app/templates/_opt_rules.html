{# The rules panel (OPTIONS_V2_DESIGN.md §7, §9): ALWAYS visible above the results. The shared block first, then the chosen strategy's own block; every field shows its label with its help as the tooltip (data-tip), its unit, and a dot when it differs from the house default. Autosave per field: each input posts itself (hx-post, "change changed, keyup changed delay:600ms" - the blur after a typed value that was already saved does not post it twice) to /options/rules?strategy=; the answer is ONLY the message line (#optRulesMsg) plus an out-of-band error slot and changed-dot for each POSTED field, so the input being typed in is never re-rendered. A value outside its bounds is stored clamped; the server names it in options:rules-clamped and the page writes the value in force back into the box (its warning stays under it until that field is saved again). A checkbox posts with a hidden "off" twin (hx-include) so un-ticking it is saved too. The server fires options:rules-changed and the page re-screens the list. Number inputs carry a step on the same grid as their min and house default (so the arrows never turn 0.50 into 0.51). A failed save writes a rose "Not saved (HTTP n)" into #optRulesMsg (the page script). A rule the data plan cannot apply (the two bid/ask rules while Massive returns no quotes, opt_rules.UNUSED_WITHOUT_QUOTES) is greyed out with its note (f.unused); it stays editable and stored, so it applies again on a plan with quotes (§13.5).
